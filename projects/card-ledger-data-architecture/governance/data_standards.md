# Data Standards: Card Ledger Data Platform

## Naming conventions
- Tables: plural snake_case nouns (`transactions`, `ledger_entries`,
  `statements`, `settlements`, `reconciliation_exceptions`).
- Columns: snake_case; primary keys are `<entity>_id`; foreign keys reuse the
  referenced primary key name exactly (`member_id`, `card_id`, `merchant_id`).
- Dates are `<thing>_date` (a date) and timestamps are `<thing>_at` (a
  timestamp with time zone). A billing period is always `period_start` and
  `period_end`, both inclusive dates.
- Boolean columns read as statements: `is_settled`, `is_reversed`.
- No abbreviations beyond the agreed list: txn is not used in column names
  (the table column is set by the canonical schema; new columns spell words out).

## Money and currency rules
- Money is never stored as floating point. Storage is either numeric(12,2) in
  major units or integer minor units (pence), and the choice is documented per
  table. This platform's pipeline uses integer pence (`amount_pence`) so totals
  reconcile exactly.
- Every money column has a sibling ISO 4217 `currency` code (three letters,
  uppercase). This platform settles in GBP; any other currency is rejected at
  ingestion and dead-lettered, not converted silently.
- Ledger entries must balance per transaction: sum of debits equals sum of
  credits. Balances are always derived, never updated in place.

## Key standards
- Business keys are stable, prefixed and zero padded (`TXN-000001`,
  `MBR-0001`, `CARD-0001`, `MERCH-001`), generated by the owning context.
- Surrogate keys may be added for joins but never replace the business key in
  events or external files.
- Event ids are derived from the business key (`evt-<txn_id>`) so replays are
  detectable and projection is idempotent.

## Audit column standards
Every table carries: `created_at` (timestamp with time zone, set by the
database default), `created_by` (system or context name), and where updates are
allowed, `updated_at`. Append-only tables (ledger entries, events, dead
letters) have no `updated_at`: corrections are new rows.

## Data quality rules
- Required identifiers are NOT NULL and validated again at event projection.
- Amounts on posted transactions are positive; reversals are separate rows
  linked to the original, never negative edits.
- Every rejected record lands in a dead letter or exception store with a
  machine-readable reason. Nothing is dropped silently.
