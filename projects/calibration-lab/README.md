# calibration-lab

A readmission risk model where the ranking is the easy part, and the probability is the product.

## Problem

A hospital discharge team gets a risk score for each patient and books follow-up calls for the ones above a threshold. If the score says 0.3, the team plans as if roughly 3 in 10 of those patients will be readmitted. A model can rank patients well and still get that number wrong, and then staffing, thresholds and budgets built on it are wrong too. This project trains a readmission model, then does the work that usually gets skipped: calibration, a cost-based threshold, and a slice audit.

## What it does

1. Generates a deterministic synthetic dataset of 3,000 discharges (prevalence 0.242) with a known ground-truth risk function. The ground truth contains an interaction and an age step that a linear model cannot represent exactly, so subgroup miscalibration is real, not staged. No patient data is used.
2. Trains logistic regression with full-batch gradient descent in NumPy. No scikit-learn, so the training step is short enough to read in a review.
3. Fits two calibrators on the validation split only, Platt scaling and isotonic regression (pool-adjacent-violators, implemented from scratch), and selects between them and the raw model by validation log loss.
4. Chooses a decision threshold on validation from stated costs: a missed readmission at £450, an unnecessary follow-up at £60. These are planning assumptions, stated in the code, not measured prices.
5. Audits the calibrated model on the test split by age band and prior-admission band, and writes a model card (weights, calibration, threshold) that `predict.py` can score from.

## Results (test split, 600 patients)

- Raw model: ROC-AUC 0.8027, Brier 0.1417, log loss 0.4395, ECE 0.0497.
- Calibrated (Platt, selected on validation log loss): ROC-AUC 0.8027, Brier 0.1415, log loss 0.4390, ECE 0.0414.
- Isotonic won validation Brier and ECE but lost on log loss, because its 0 and 1 steps, fitted on 600 validation rows, punish hard when they are wrong. On the test split its log loss was 0.6491 against 0.4390 for Platt. Selection by log loss exists in this pipeline because of that result.
- Threshold chosen on validation: 0.11, not 0.5. At that threshold the test cost was £19,710 against £41,280 at the default 0.5, with 7 missed readmissions out of 146.
- Worst slice by Brier: patients with 2 or more prior admissions, 0.182, and the single-prior-admission slice ranked worst at ROC-AUC 0.6959. The headline AUC of 0.80 hides both.

Full numbers are in `report.md` and `artifacts/metrics.json`, regenerated by every run.

## Run it

```bash
pip install -r requirements.txt
python pipeline.py          # trains, calibrates, writes report.md and artifacts/
python -m pytest tests/ -q  # 8 tests
python predict.py '{"age": 78, "prior_admissions": 2, "length_of_stay_days": 6, "comorbidity_count": 3, "medication_count": 9, "follow_up_booked": 0, "weekend_discharge": 1}'
```

Sample output from `predict.py` for that patient: readmission risk 0.8162, flagged for follow-up at the 0.11 threshold. A 45-year-old with no prior admissions and a follow-up booked scores 0.0091 and is not flagged.

## Files

- `data.py`: synthetic generator and stratified split
- `model.py`: logistic regression, gradient descent
- `calibration.py`: Platt scaling and isotonic regression
- `metrics.py`: ROC-AUC, Brier, log loss, ECE, costed confusion
- `pipeline.py`: end-to-end run, threshold and slice audit, model card
- `predict.py`: single-patient scoring from the saved model card
- `tests/test_calibration_lab.py`: 8 tests, including PAVA monotonicity and an end-to-end pipeline run

## Tech stack

Python, NumPy, pytest. Deliberately no ML framework: calibration and evaluation code is the subject of the project, so it is written out rather than imported.

## Limits

Synthetic data with a known generator, so absolute numbers do not transfer to a real ward. The point is the evaluation discipline: calibrate on a separate split, select with a proper scoring rule, price the threshold, and read the slices before quoting the headline metric.
